## V1 — Architecture, Design and Threat Modeling

- [ ] V1.1 A complete threat model exists for the feature (threat-model.md) and is current
- [ ] V1.5 All components, trust boundaries, and data flows are documented
- [ ] V1.8 Security requirements are traceable from spec to verification (SR-###/SAC-### → matrix → tasks → evidence)
- [ ] V1.9 Security controls are centralized and consistent (validation, authZ, encoding, logging)

## V2 — Authentication

*Applies if the feature authenticates anyone or anything.*

- [ ] V2.1 AuthN is required for all non-public operations; public surface is explicitly allow-listed
- [ ] V2.2 Credentials stored using approved hashing (Argon2/bcrypt/scrypt) with per-user salt
- [ ] V2.3 Credential recovery flows resist account takeover (no user enumeration, time-safe)
- [ ] V2.4 Credential lookup is resistant to timing/user-enumeration oracles
- [ ] V2.5 MFA available/enforced per policy; recovery codes handled as secrets
- [ ] V2.7 Rate limiting and lockout on authentication endpoints

## V3 — Session Management

*Applies if sessions/tokens exist.*

- [ ] V3.2 Tokens are random (≥128-bit entropy), generated by approved libraries
- [ ] V3.3 Session termination: logout, expiry (idle + absolute), re-auth on privilege change
- [ ] V3.4 State-changing actions require fresh/intact session state (token rotation where applicable)
- [ ] V3.5 Tokens transmitted only over secure channels; cookie flags Secure/HttpOnly/SameSite
- [ ] V3.6 Logout invalidates the session server-side (not just client cookie clearing)

## V4 — Access Control

- [ ] V4.1 Deny-by-default enforcement at a single trusted layer (server-side)
- [ ] V4.2 Object-level authorization on every access (IDOR/missing function level covered)
- [ ] V4.3 Least privilege: permissions match roles; no wildcard grants
- [ ] V4.5 Anti-automation on business-critical flows (SR-ABUSE)
- [ ] V4.7 Administrative interface protected with additional controls (MFA/allow-list where applicable)

## V5 — Validation, Sanitization and Encoding

- [ ] V5.2 All input from untrusted sources validated (schema: type, length, range, format)
- [ ] V5.3 Output encoding matches context (HTML, URL, SQL, OS command, LDAP, XML/JSON)
- [ ] V5.4 Query parameterization everywhere; no string-built queries
- [ ] V5.5 Deserialization of untrusted data avoided or strictly validated
- [ ] V5.6 Mail/file/URL handling validated (header injection, path traversal, SSRF — http/https only, reject localhost/loopback/private/reserved hosts)

## V6 — Stored Cryptography

- [ ] V6.1 All cryptographic operations use vetted libraries and current algorithms (no custom crypto)
- [ ] V6.2 Randomness from approved CSPRNG
- [ ] V6.3 Cryptographic keys managed in a secret manager; rotation supported
- [ ] V6.4 Secrets/keys not committed to code, config templates, or tests

## V7 — Errors, Logging and Auditing

- [ ] V7.1 Security events logged (authN result, authZ denials, privilege/config changes)
- [ ] V7.2 Logs protected from injection; control characters sanitized
- [ ] V7.3 Time sources synchronized; timestamps UTC and consistent
- [ ] V7.4 Audit records contain actor, action, target, timestamp, correlation
- [ ] V7.5 Sensitive data (credentials, tokens, PII) never logged
- [ ] V7.7 Log access restricted; audit trail retention per policy

## V8 — Data Protection

- [ ] V8.1 Data classified (Public/Internal/Confidential/Restricted); handling matches class
- [ ] V8.2 Sensitive data encrypted at rest
- [ ] V8.3 Sensitive data protected in transit
- [ ] V8.4 Unnecessary collection/discovery avoided (minimization; no sensitive data in caches/exports beyond need)

## V9 — Communications

- [ ] V9.1 TLS 1.2+ for all external and internal service channels
- [ ] V9.2 Certificate validation enforced (no verification disabled)

## V10 — Malicious Code (defense side)

- [ ] V10.2 Third-party code pinned and integrity-verified (lockfile hashes, trusted sources)
- [ ] V10.3 Build/CI pipeline integrity protected (pinned actions, reviewed workflow changes)

## V11 — Business Logic

- [ ] V11.1 Business flow limits enforced (quantities, values, frequencies)
- [ ] V11.2 Anti-automation on high-risk business transactions
- [ ] V11.3 High-value logic has deception/resilience (e.g., order totals computed server-side only)

## V12 — Files and Resources

- [ ] V12.1 File uploads: type, size, content validated; stored outside web root; served safely
- [ ] V12.4 Untrusted files processed in isolation (sandbox/AV scan where applicable)
- [ ] V12.5 URL fetching (if any): scheme restricted to http/https; hosts validated (reject localhost, loopback, private, reserved ranges)

## V13 — API and Web Services

*Applies if the feature exposes APIs (also complete api-security.md).*

- [ ] V13.1 API authN/authZ complete and consistent per endpoint
- [ ] V13.2 URL rewriting/param tampering does not bypass controls
- [ ] V13.3 Error responses generic; no stack traces or internals
- [ ] V13.4 JSON/XML services validate content-type and schema strictly

## V14 — Configuration

- [ ] V14.1 Secure defaults shipped; libraries/platforms on supported versions
- [ ] V14.2 Production configuration hardened ("debug" off, admin surfaces protected)
- [ ] V14.3 Environment segregation (dev data never in prod; secrets per-environment)
- [ ] V14.4 Administrative functionality minimal and protected
- [ ] V14.5 Security headers applied to every response (web)
